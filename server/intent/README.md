# Text-to-music interpretation

`POST /api/intent` accepts the bounded shared `InterpretRequest` and returns a shared `InterpretResponse`. Music playback remains independent. Configure `CRUSOE_API_KEY` only on the server; a missing key produces a friendly error and does not prevent playback. The endpoint/model are fixed to Crusoe's OpenAI-compatible chat-completions API and `nvidia/Nemotron-3.5-Lightning-30B-A3B`. Clients cannot supply credentials, model names, endpoints or retrieval URLs.

The relay accepts JSON from a matching Origin/Host authority only, with HTTP or HTTPS origins (the latter permits a TLS-terminating reverse proxy). A dev proxy must preserve the original Host (`changeOrigin: false`) and proxy `/api/intent`, as well as the separate music WebSocket path. No CORS or wildcard origins are enabled. Limits are 16 KB request bodies, a five-second body read, 12 requests per minute across the server and two in flight. The interpreter has one 25-second budget including all provider and lookup work. Browser disconnect and relay shutdown cancel pending work.

Each interpretation uses `json_object` output with the exact schema and examples in the system prompt, disables thinking, and limits visible generation to 900 tokens. This mode passed a real full-interpreter probe on the fixed Crusoe endpoint. Strict `json_schema` requests returned empty one-token responses in that probe, so they are not the default. A server-only `INTENT_OUTPUT_MODE=json_schema` option remains for explicit compatibility testing. Both modes apply identical strict local validation and repair limits; clients cannot select the mode. Application validation still enforces enums, exact keys, bounds and recipe feasibility. One repair is allowed for malformed model output, across the entire interpretation. HTTP/auth/billing/rate errors are never retried. A reference request can require one additional model call after lookup, so the maximum is three model calls per interpretation. HTTP 402 is an account-configuration error; provider error bodies and secrets are never returned or logged. Request text and responses are not logged by this component.

Explicit constraints must leave at least one of the 375 one-feature-per-group recipes. Inferred styles are hints, and `contextPrompt` carries only supplemental qualities; a vocabulary-word check rejects obvious duplicate feature text. A conservative English/Chinese alias check demotes unnamed hard requirements to hints and rejects unnamed exclusions, unless inherited from the prior intent. This check cannot prove semantic coherence or model faithfulness. Other languages or ambiguous named references may require clarification. Model routing and source interpretation still need evaluation: schema validation cannot establish identity or trait entailment. No claim is made that schema validity establishes musical quality.

Song/artist references use at most one fixed-host Wikipedia search plus an introductory plain-text extract request, each with redirects disabled and a shared six-second lookup budget. Queries are at most 160 characters, three pages are retained, extracts are capped at 1,200 characters, and each HTTP response is capped at 64 KB. A bounded 64-entry cache lasts ten minutes. Disambiguation pages are filtered. The model sees retrieved text as untrusted evidence and is instructed to clarify ambiguity, avoid unsupported audio facts and not quote lyrics. Public source titles and HTTPS URLs are copied from retrieved pages using IDs, never invented by the model. Empty/failed lookup returns a clarification rather than a fabricated reference. Obvious song requests cannot return an ungrounded ready result.

Provider and lookup behavior is tested with injected fetch functions, without credentials or generation. A real deployment must verify provider schema acceptance and reference availability separately; advertised structured-output capability alone does not prove compatibility.
