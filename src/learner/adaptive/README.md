# Adaptive learner experiment

This optional module leaves `src/learner/index.ts` intact. Import the same four functions from `src/learner/adaptive`, plus `inspect` for diagnostics. It is deterministic, synchronous, browser-safe, and has no storage, clocks, network, or timers.

```ts
let state = createLearner(42, 'focus'); // focus | relax | energy | explore | crazy
let target = initialTarget(state);
({ state, target } = processVote({
  state, audible: heardBlend, currentTarget: target, vote: 'up', evidenceWeight: 1,
}));
target = evolveNoVote({ state, target, step: 1 }); // after adequate exposure
const diagnostics = inspect(state, target);
```

Optional validated `MusicIntent` session context can be supplied to `initialTarget(state, intent)`, `processVote({ ...args, intent })`, and `evolveNoVote({ ...args, intent })`. `applyIntent({ state, currentTarget, intent })` selects a target using the latest saved state; omit `intent` to clear the request. Neither applying nor clearing changes any model, evidence, vote, seed, recovery or rejection-history field. The shared adapter exposes the same operations. Intent is caller-owned session context, not a persisted learned feature or an implicit switch to another purpose's saved profile.

Explicit supported requirements/exclusions filter the full recipe catalog **before** local search, credible probes and style escape. A required ID owns its group: `requiredFeatures: ['jazz']` means jazz-only, including for a held transition blend. A Like still learns the full actually heard blend, but if it contains forbidden outgoing ingredients, it keeps the compatible current destination instead of reinstating them. Repeated dislikes escape through the first two mutable groups (genre, instrument, mood, texture order); jazz-only therefore varies instrument and mood. If constraints leave only one recipe, downvotes and freshness hold it with an explicit explanation. Invalid/infeasible requests throw before any feedback calculation rather than silently relaxing restrictions.

Inferred feature/purpose hints add at most `0.22 / (1 + evidence / 12)` utility during ranking. This bounded, tunable prior fades with actual learned evidence, so it can influence a cold start without continually forcing a rejected inferred feature. Existing learned utility, uncertainty, transition cost and seeded ranking remain. Hints do not enter A/b or become permanent renderer phrases. Omitting intent preserves the exact pre-extension learner trace, including seeds and prompt wording.

The renderer appends stable `contextPrompt` text (weight 0.5) and at most three paired `avoid` descriptions (total weight 0.3), rebuilding them from the current intent on every action. Six possible held feature prompts plus these four overlays fit the relay's ten-prompt limit; each text remains within 200 characters. Controllers must separately handle old/new prompt unions during transitions, which can exceed that limit even when both endpoints fit. Free descriptions and avoidance wording are requests to the generator, not enforceable acoustic constraints or additional learned dimensions. Their meaning cannot be checked by feature-enum validation; the interpreter should keep inferred feature suggestions out of persistent descriptive text and place supported explicit restrictions in the structured constraint arrays. Clearing or replacing intent removes its old descriptive overlays.

While an intent is active, feature wording uses neutral vocabulary rather than profile-specific embellishments. This prevents Crazy's fixed fast/frenetic language from contradicting a new slow request; retained Crazy variants are not eligible neutral phrasings. The saved purpose, scoring prior and model remain unchanged. `Target.intentRendering` records only this renderer context so clearing restores profile-specific wording even for retained controls. It carries no preference evidence, and targets created without intent retain the original behavior and shape.

Both thumbs fit the whole normalized heard blend with a full 18 × 18 regularized linear model. They do not independently reward or punish every ingredient. With `x` normalized over all valid audible features, reward `r` of ±1, and evidence weight `w` clamped to 0..1:

```
g = 0.995 ** w
A = g A + (1 - g) 0.35 I + w x xᵀ
b = g b + w r x
theta = solve(A, b)
```

A Like can optionally include `comparison: { previous: rejectedHeardBlend }`. The controller supplies this only for a recent, adequately heard, meaningfully changed blend after an explicit Dislike, and consumes the reference once. The core checks positive effective weight, valid reference features, and distinct normalized mixtures. For this case only, split the existing weight: `a = 0.5w`, `p = 0.5w`, `d = x - previous`. Replace the new observation terms with:

```
A += a x xᵀ + p d dᵀ
b += a x + p 2d
```

The margin 2 is the difference between the existing +1 Like and −1 Dislike labels. Total effective evidence stays `w`; `pairwiseEvidence` tracks the discounted comparison share `p`, not an extra vote. Difference vectors are not renormalized, so tiny changes cannot become full-size directions. Their unchanged normalized coordinates receive zero pairwise credit; the absolute half still supports the liked blend. When a comparison changes several ingredients or changes their normalized shares, it remains a bundled preference comparison, not identification of the responsible ingredient. No comparison, invalid/identical references, downvotes and zero-weight actions retain the original update. Scheduled novelty and immediate Like holding are unchanged. This is a bounded learning heuristic, not a causal measure of “faster”; tempo is not an independent feature or a measured audio property here.

Cholesky triangular solves compute coefficients and candidate uncertainty without explicitly inverting the matrix. Empty audible evidence, zero weight, or non-finite weight produces no update or forgetting. Every explicit click still increments `votes`. `scores` exposes the regression coefficients for compatibility; these are neither probabilities nor independent causal preferences. Positive/negative evidence totals are discounted effective weights, not observed acceptance rates.

A bounded recovery heuristic addresses abrupt reversals that conservative forgetting alone handles slowly. A dislike counts as surprising only when the **before-vote** prediction is above 0.2 and directional information above 0.6. Collect two effective evidence units across at least two meaningfully different heard blends (normalized total variation at least 0.15); cap any one blend's contribution at one. Then retain 25% of old `A - 0.35 I`, `b`, and evidence totals, and add the latest feedback at its full supplied weight. Recovery is disarmed until an effective positive vote, preventing repeated resets within the same rejection episode. Zero-weight clicks cannot accumulate surprise, rearm recovery, or discount evidence. Rejecting an already predicted-poor exploratory option does not count as surprise. State holds a bounded six-blend surprise ledger and exposes recovery count/latest recovery vote for diagnostics.

This is one predeclared revision after an independent abrupt-reversal simulation exposed slow adaptation. The 25% retention and thresholds are uncalibrated heuristics, not an inferred change-point probability. Different prompt blends and controller-supplied weights are only a proxy for independent listening exposure; the learner cannot prove that two clicks reflect independent audio judgments. The correction needs before/after evaluation on the same fixtures, including stable and noisy tastes, rather than assuming stronger forgetting always helps.

Selection evaluates all 375 one-genre, one-instrument, one-mood, one-texture recipes. Prediction, model uncertainty, a weak purpose hint, transition cost, and seeded tie noise rank candidates. Ordinary purposes favor mood/texture; Crazy also favors electronic/synth or percussion, energetic mood and rhythmic texture. Every purpose is a soft prior, excludes no genre and changes no evidence. Model uncertainty retains the ambiguity of ingredients only heard together. `inspect().coverage` is average marginal information reduction, and `information` concerns the current blend only; neither is a calibrated confidence percentage. Phases depend on current predicted support and directional information, not just vote count. Repeated effective rejections reopen search. These are tunable heuristics, not statistical confidence bounds.

Consecutive distinct dislikes also have a selection-only escape policy. Keep up to three normalized rejected heard blends since the last effective Like; add a blend only for positive evidence weight and normalized total variation at least 0.15 from all retained references. At three distinct rejections, an effective downvote forces a broad recipe search that leaves both pending genre and instrument, and avoids the rejected audible genres/instruments wherever available. If a transition already contains the entire palette, use the most novel feasible style while still leaving the pending style. Earlier dislikes keep the existing exploratory/local ranking. Once active, this broader escape remains available until an effective Like clears the ledger and reopening streak. Zero-weight dislikes do not escalate it, zero-weight Likes do not clear it, and scheduled silence changes none of it. The escape filter does not discard A/b or learned scores; the earlier, independently gated surprise-recovery mechanism still operates as documented above. `inspect().rejectedBlendCount` and `Target.lastDecision.styleEscape` make the selection reason reviewable. In a fixed 32-seed supported-style test, the first two distinct rejections retained both style components; the third changed both in all seeds. This verifies the explicit filter, not musical quality.

The renderer preserves the team's vocabulary phrasings for every existing profile. Crazy adds seeded experimental instrumental wording for electronic, synth, percussion, energetic, rhythmic and layered controls, with explicit fast/frenetic rhythm language. It keeps the same 18 feature IDs and prompt weights; it does not increase gain, set BPM, or reset the generator. Learned evidence can override its initial feature preference. Crazy wording is still a prompt request, with no promise of a measured tempo or perceptual effect. Initial and newly introduced features receive a seeded phrasing; retained features keep their exact prompt text. `Target.phrasingSalt` stays fixed through the session so a mid-transition like can restore the original wording of an outgoing feature even after it left the pending target. Likes hold prompt text and weights, allowing controller equality checks to avoid needless ramps. Adaptive scheduled variations already change recipe identities, so this module does not additionally reword a retained feature at the baseline learner's 35% cadence. Learning remains over the same 18 feature IDs; variants such as felt/Rhodes/prepared piano differ musically, and the model does not claim to learn those subtypes separately.

A like holds the projected heard blend immediately. A dislike excludes the heard and pending recipe identities; it often searches nearby when the current family is supported and searches more broadly when evidence is weak or rejections accumulate. It does not always replace the genre. Scheduled `evolveNoVote` picks a nearby identity variation, with occasional broader probes; supported probes normally stay within 0.25 predicted reward of the current blend. Every scheduled change preserves all state, including A, b, scores, votes, RNG seed and evidence totals. Silence never becomes a synthetic thumb. `step` is a deterministic novelty counter; absent one, target decision metadata advances it. There is no retained exposure-history model in this first version, so the controller must schedule adequate listening windows.

`Target.lastDecision` explains the action and records its step, prediction and uncertainty. `inspect(state, target)` returns `phase`, `reason`, `evidence`, ranked coefficients, prediction, uncertainty, purpose, and information diagnostics. These diagnostics describe the prompt model, not acoustic measurements. UI should present them as experimental explanations and avoid calling coefficients “favorite ingredients” or uncertainty a likelihood.

The controller supplies the heard mixture after accounting for buffering and an `evidenceWeight` to limit correlated rapid clicks. This module cannot infer independent listening exposure from click count. The controller owns ramps, send cadence, timing, playback, and revisions. For a matched memory ablation, reset A, b, scores and effective evidence totals from `createLearner(state.seed, state.purpose)` while retaining action/RNG history and target metadata; surprise bookkeeping is policy history and cannot trigger without model-supported predictions. `isAdaptiveState(unknown)` in `adapter.ts` validates saved JSON before use: all model/policy fields, bounded finite values, normalized surprise observations, consistent evidence totals, symmetric positive-definite matrices bounded below by the ridge prior, and scores matching the solved model. It rejects incomplete older experimental states, including those missing `pairwiseEvidence` or `rejectedBlends`; migration is not implicit. Storage remains outside the pure learner.

This is a practical MVP hypothesis. The additive model cannot represent arbitrary genre/instrument interactions, prompt controls may not match audible content, conservative forgetting can adapt slowly, and uncertainty/probe weights require comparison with simple baselines. Repeated likes identify support for a blend without identifying every ingredient. No convergence or listening-quality claim follows from the unit tests. Run synthetic baselines and real listening evaluation before adopting it as an improvement.

Directional tests additionally cover exact pairwise updates, zero credit for unchanged coordinates, future recipe changes in fixed synthetic episodes, invalid/correlated references, JSON round trips and malformed states, plus Crazy determinism, stable wording and soft-prior override. The fixed 32-seed fixture selected energetic/rhythmic controls 48 of 64 opportunities after four rejected→liked episodes versus 11 before learning; this is a code-behavior check, not measured listener benefit or evidence that the new rule outperforms the prior learner.

Validation: `vitest run src/learner/adaptive`, then the repository typecheck/build. Tests cover the exact coupled update, fractional/zero evidence, heard-vs-pending attribution, uncertainty under repeated co-occurrence, purpose priors, unchanged silent evidence, continued post-like variety, replay, finite long-run behavior, exact recovery algebra/latest-feedback retention, and suppression of resets for correlated or expected-poor rejections.
